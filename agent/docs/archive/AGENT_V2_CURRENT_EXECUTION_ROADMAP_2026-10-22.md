## 每阶段纠偏检查

进入下一项之前必须同时回答：

- 本项是否直接对应当前真实阻塞？
- 实际变更是否仍在已冻结的文件和功能范围内？
- 测试结论与真实运行结论是否分开记录？
- 是否引入了新的平行框架、企业信任设施或未经证明的前置条件？
- 路线图状态、PR 描述和真实运行状态是否一致？

任一答案为“否”或“不确定”时停止推进，先缩回当前工作包。不得通过增加更多阶段、契约或基础设施来延后真实 002 验收。

## 完成口径

代码合并或测试全绿只代表开发完成。只有真实 002 验证证明七阶段能继续，Agent 才算可投入实际建站。

以下情况不算 Agent 缺陷，也不得通过绕过规则消除：第三方 429/403、站内登录或验证码需要用户处理、缺少第一手资料，以及用户尚未批准部署。它们必须显示为 `PARTIAL`、`BLOCKED` 或 `WAITING_FOR_USER`。

以下情况属于 Agent 缺陷，必须修复：相同合法数据在模块间格式不兼容、已完成产物因最终汇报丢失、恢复快照不能继续、失败状态退出码错误、审批绑定可被绕过、草稿被公开发布。

## 非当前路线

旧 V2 生产信任体系只在未来出现明确的多人、多租户或敌对执行环境需求时重新立项。不得为了“以后可能需要”继续扩张当前个人版 Agent。
