# 浏览器调研工具边界（下一阶段实现约束）

现状：Codex CLI 在 workspace-write 沙箱中访问本机 127.0.0.1:3456（本地浏览器代理）和 127.0.0.1:9222（CDP）时出现 EPERM，Mac 宿主进程本身可访问官方网站。此处不可通过 danger-full-access、拷贝 Cookie、暴露 CDP 到公网或关闭沙箱绕过。

建议采用受控的「宿主浏览器操作层」而非由 Codex 在沙箱内直接持有浏览器连接：
1. 宿主服务仅开放 allowlist 的只读网页操作，例如打开指定官方 URL、抽取页面标题、正文、链接及来源时间，并把观察结果保存至本次任务隔离目录。
2. Agent 为每个浏览器请求提交结构化任务：run_id、stage、目标 URL、期望证据、允许的读操作、可写产物路径。拒绝任意脚本执行、任意本地文件读写、任意内部地址/localhost 请求。
3. URL 必须是 HTTPS 公网域名；校验重定向目标及 DNS 解析，禁止 loopback、内网和元数据服务。限制次数、页面大小、耗时；全部留痕。
4. 宿主侧完成浏览器访问，输出 snapshot.json（URL、timestamp、title、text_excerpt、链接、提取方法、错误）。Codex 仅读取快照文件，不获得网络代理或浏览器敏感凭据。
5. 任何需要登录网页、上传、下载、点击、截图、favicon.io 生成或第三方服务交互的操作，必须单独审核能力和授权边界。不可因为网页可访问就将 Skill 标记通过。
6. 浏览器证据过期、来源不可访问、重要素材缺失，应返回 BLOCKED / WAITING_FOR_USER，不得伪造研究文档。

当前文件为规格说明，不代表宿主浏览器桥已实现或已验收。
