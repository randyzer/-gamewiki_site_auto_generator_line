# Source and verification policy

## Discovery is not evidence

Serper result titles, snippets, ranking, and estimated result counts help identify candidate pages. They are not a substitute for opening the page. A material file may cite a URL only after confirming it loads and contains the summarized claim.

## Source selection

For each keyword, aim for:

- One or two high-quality webpages directly addressing the intent.
- One relevant YouTube video with usable subtitles when available.
- One official source when it contains keyword-relevant detail.

More sources are not automatically better. Prefer the smallest set that covers the topic and allows important claims to be checked.

Avoid:

- Search-result aggregators and doorway pages.
- Pages that merely copy another source.
- Undated pages for mechanics known to change, unless clearly labeled as uncertain.
- Broken, deleted, region-blocked, or inaccessible URLs.
- Competitor homepages when only a relevant deep guide page is needed.

## Cross-validation

Classify each extracted statement:

- **Stable identity fact**: developer, platform, genre, basic mechanic.
- **Version-sensitive fact**: values, drop rates, skill effects, unlock conditions, tier lists, active codes.
- **Opinion or strategy**: route, build, ranking, recommended order.

Important version-sensitive facts require two independent sources whenever possible. One current official source can be sufficient when it is explicit, but still record its version/date. Label opinions as recommendations, not facts.

## Conflicts

When sources disagree:

1. Check publication/update date and game version.
2. Prefer an explicit current official statement.
3. Prefer a maintained specialist source over an anonymous or copied page.
4. Preserve the discrepancy and mark it `待确认` if it cannot be resolved.

Never average conflicting numbers or silently choose the more convenient claim.

## YouTube transcripts

- Manual subtitles outrank auto-generated subtitles.
- Preserve timestamps for material facts and actionable steps.
- Treat automatic transcription of names, values, or codes as error-prone and confirm elsewhere.
- Do not use a video's title or description as if it were transcript evidence.
- Do not reproduce full transcripts in the deliverable.

## Freshness

Record access date for every source and publication/update date when available. For live-service games, mark version-sensitive content for review after major patches. Do not call a code active unless it was confirmed against a current source during the run.

## Status rubric

`COMPLETED` requires enough directly relevant material for a future page and cross-validation of important claims. `PARTIAL` is appropriate when the material is useful but thin, stale, or partly unconfirmed. `BLOCKED` is appropriate when access, tooling, or lack of reliable sources prevents a useful evidence set.
