## 4. Root Cause

The v2.5 generated media audit treated every rendered `<img>` as content media. A valid semantic header logo such as `/logo.svg` could therefore fail because it was not a registered `/media/` content asset.

This was a role-boundary defect, not an image accessibility defect. Global HTML accessibility validation already checked image `alt` attributes and remains global.

## 5. Content Media Vs Site Chrome Implementation

Implemented in `scripts/media-validation.ts` and `scripts/audit-build.ts`.

Content media validation now applies to Starter-owned content media output:

- `figure.game-media[data-media-id]`
- fixed page placements such as `data-media-placement="hero"`, `gallery`, and `trailer`
- registered YouTube-nocookie iframe output from validated content media assets
- registered local video output and poster checks

Site chrome images are no longer rejected merely because they are not `/media/` content assets. The broad all-page `<img>` content-media gate was removed.

Global image accessibility remains in `src/core/html-audit.ts`; every `<img>` still must declare `alt`.

## 7. Media Readiness Implementation

Implemented in:

- `src/core/media-readiness.ts`
- `scripts/validate-site.ts`
- `tests/media-readiness.test.ts`

The readiness check is optional, explicit, and planning-only:

- It reads `MEDIA_DECISION_TABLE.md` only when that file exists.
- It parses a narrow Markdown table shape with `Page ID`, `Route`, `Priority`, `Status`, and optional `Rationale`.
- It keys rows by existing Runtime Page Inventory `pageId` or `route`.
- It does not add media lifecycle fields to Runtime Page Inventory.
- It does not alter the media manifest contract.
- It does not infer priority automatically.

Severity policy implemented:

- Homepage `HIGH PRIORITY` unresolved: blocking validation error
- Non-homepage `HIGH PRIORITY` unresolved: non-blocking warning
- `RECOMMENDED` unresolved: non-blocking informational signal
- `NO MEDIA NEEDED`: valid and non-blocking
- No optional readiness artifact supplied: backward-compatible pass

Planning input is not publication authority. Runtime Page Inventory remains the publication SSOT.

## 13. Architecture Principles

High Cohesion:

- Content media rendering and audit rules remain in `src/data/media/*`, `src/components/media/*`, and `scripts/media-validation.ts`.
- Chrome logo checks are narrow helpers in `scripts/media-validation.ts` and build/validate aggregation scripts.
- Media readiness planning signals live in `src/core/media-readiness.ts`, separate from renderers and publication inventory.

Low Coupling:

- `brand.logoPath` is consumed by `src/core/brand.ts` and `src/components/Header.astro` without coupling logos to `media.json`.
- Readiness decisions reference existing `pageId` or `route`; they do not mutate Page Inventory.
- Build audit composes chrome, HTML accessibility, and content media validators without merging their responsibilities.

Modular Design:

- `scripts/validate-site.ts` remains the CLI aggregation point.
- `scripts/audit-build.ts` remains generated-output audit aggregation.
- `src/core/media-readiness.ts` exposes reusable pure parsing and signal functions.
- Header remains a presentation component fed by config-derived brand presentation.

Adaptable Design:

- Text-only branding remains valid.
- Configured semantic logo rendering is supported.
- No-media pages remain valid.
- Projects can opt into media readiness by adding the planning artifact.

Stable Core / Flexible Edge:

- Stable Core receives only repeated technical boundary fixes and the lightweight explicit planning signal.
- Provider-specific fallback visuals and media workflow decisions remain project-edge patterns.

## 16. Regression Expectations

Future regressions should be caught when:

- a header logo is misclassified as content media;
- configured logo paths do not exist;
- the header logo fails to render in generated output;
- the header home link loses its accessible name;
- a content media image points at a missing `/media/` file;
- global image `alt` validation is weakened;
- a homepage high-priority unresolved media decision is allowed to pass;
- non-homepage high-priority unresolved media is accidentally promoted to a universal blocking quota;
- missing `MEDIA_DECISION_TABLE.md` stops being backward-compatible.

## 17. Targeted Parser Correctness Repair

Follow-up review found one required pre-freeze issue: when `MEDIA_DECISION_TABLE.md` existed but was malformed, the parser could return an empty decision set with no errors. That failed open and could hide homepage `HIGH PRIORITY` unresolved media.

Narrow repair:

- `parseMediaDecisionTableMarkdown` now returns `{ decisions, errors }`.
- Required columns are exactly `Priority`, `Status`, and at least one locator column: `Page ID` or `Route`.
- Accepted `Priority` values remain `HIGH PRIORITY`, `RECOMMENDED`, and `NO MEDIA NEEDED`.
- Accepted `Status` values remain `resolved` and `unresolved`.
- A present empty file, malformed table structure, missing required columns, unsupported enum values, or a non-empty row without `Page ID`/`Route` now produces deterministic parse errors.
- `scripts/validate-site.ts` surfaces parse errors through the existing validation error path.
- Absence of `MEDIA_DECISION_TABLE.md` remains backward-compatible and valid.

No scope expansion was made:

- No new dependency.
- No rights, waiver, Game Recognition, visual approval, acquisition, publication-state, or complete lifecycle parsing.
- No Runtime Page Inventory, media manifest, Header, logo, YouTube, engine, or package-contract change.
