1. **Page Inventory 职责污染？** 当前 optional liveStatus 把游戏/内容实时观察的 state/observedAt/source/evidenceNote 带进页面身份/发布数据，是超出窄 page truth 的实验职责扩张。没有发现它改变 publicationStatus/route/indexability 判定，所以不能称现有发布行为已被破坏。
2. **移除后边界？** 只删实验成员，原 pageId/route/publication/indexability、publishedAt/updatedAt/sources 与 strict validation 保留，恢复该项 page-truth 窄边界；不顺手迁移 content/facts/media。
3. **其他 runtime authority？** 全量引用显示只有 freshness 的 input/output 与两个文章展示消费者；无 03A/B/C/search、legalActivation、SEO、路由、索引或 facts/tool 对 liveStatus 的运行依赖。evidenceNote 是独立来源隐私字段，绝非 liveStatus 的专属 authority。
4. **迁移兼容层？** 本地数据无 liveStatus，历史用法为合成输入。计划不需要 adapter、旧字段吞掉逻辑、schema dual-read 或新输入模型。
5. **可直接删吗？** 正式 Review 基线已经确认；本地可读真实 inventory/JSON 中未发现 liveStatus，因此本计划可提出直接删除这些 runtime 成员，无 migration adapter。OQ-02 仅保留“未来如发现真实外部数据”的条件，不因理论兼容性阻塞此计划。entry .strict() 将显式旧字段作为未知键拒绝；若发现真实采用数据，先 STOP，列出准确项目/字段，另行有限数据处置，不自动加框架或迁移到另一 schema。

DEFER 的意思是 V2.7 不提供此机制，未来如真实采用证明需要另提有限产品方案；本轮与拟议 removal 均不设计替代 Live 模型、不迁移 live authority、不生成 telemetry。
