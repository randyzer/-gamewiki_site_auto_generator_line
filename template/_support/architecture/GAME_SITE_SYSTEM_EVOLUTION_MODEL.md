# 三件套关系与同步演进核对

日期：2026-10-01。范围：关系、责任及同步需求；不是新架构蓝图或演进路线。

## 原体系如何协作

| 工件 | 权威与职责 | 本次应怎样演进 |
| --- | --- | --- |
| GAME_SOP | 研究、覆盖、来源、规划、视觉/媒体、验收、上线和维护方法 | 将真实项目失败转为可验证的生产要求，明确能力选择、证据和人工责任 |
| GAME_CODEX_MASTER_PROMPT | 把 SOP 与技术契约落实为执行阶段、边界、Gate、HARD STOP 和证据要求 | 同步新流程与命令，禁止跳过证据、凭技术 PASS 宣告商业完成或混用三件套版本 |
| GAME_SITE_STARTER | 可复用技术实现、配置/数据模型、渲染、发布过滤、构建与审计 | 保留原有有效能力，修复可复用缺陷，提供经过验证的新能力与迁移说明 |
| Real Game Project | 具体游戏的内容、事实、媒体、主题、功能选择和实际运营 | 提供真实采用与回归证据，不把项目配置或内容硬塞回通用 Starter |

依据：Master Prompt v2.6.5 的 0.1–0.4、Project Boundary；SOP 的 manifest、主 SOP 与 QA；Starter README 的 authority / adoption / release boundary。

## 是否要同步 SOP 与 Master Prompt

**需要。最终产物是三件套的兼容组合。** 本次升级涉及生产方法、采用步骤、安全边界、视觉/媒体、玩家价值和验收证据，只改技术代码会让旧流程和执行指令继续驱动错误行为。

每个改动按责任同步，不机械修改所有文件。例如纯 CSS 缺陷可仅改 Starter；若增加采用前残留检查或浏览器证据要求，Starter 提供命令与机制，SOP 定义何时及凭何证据验收，Master Prompt 强制执行与停止条件。

| 变化 | Starter | SOP | Master Prompt |
| --- | --- | --- | --- |
| 法律与身份安全 | 默认不作无证据声明，显式配置与审计 | 声明来源、审核与激活责任 | 阻止推断主体/关联关系或草稿公开 |
| 生产残留 | 检查技术与采用说明 | 上线完成标准与例外边界 | final 检查与停止条件 |
| 导航与浏览器 | 交互实现和可运行验证 | 用户可达性与支持范围 | 执行证据、缺项/跳过失败 |
| 游戏识别、媒体、内容模式 | 可复用实现接口与约束 | 选型、来源、权利、玩家任务和人工验收 | 执行批准方案、防止泛化套皮与无依据完成声明 |
| 回归与交付 | 保存能力与技术证据 | 真实项目回归和三件套验收 | 检查准确版本、兼容组合与发布 Gate |

此表是关系盘点，不分配新实现任务或改变已批准能力 ID。
